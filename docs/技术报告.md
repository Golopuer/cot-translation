## 1. 背景与目标

### 1.1 原始需求

用户需要：把 Agent（主模型）的**英文思考过程（思维链）自动翻译成中文「人话」**，显示在对话旁边，带开关，且**本地翻译、不依赖云端**。

关键约束随需求澄清逐步收敛为：

1. **本地翻译**（不调云）→ 用本机 `Qwen3.5-0.8B`（权重由用户提供，复用 ComfyUI 的 torch 环境）。
2. **说人话**：不是逐字机翻，而是口语化、抓重点、术语/路径/命令保持英文原样。
3. **摘要式解读**：用户最终确定要「摘要式解读」，而非逐句翻译。
4. **监听而非拦截**：绝不能修改主模型的思维流本身，只能旁路观察。

### 1.2 一句话现状

本地翻译链路（Qwen3.5-0.8B on CUDA）已跑通；输出格式的定稿提示词经 A/B 实测后找到了「既能让 0.8B 扛住、又能修掉否定词漏译」的版本（即本报告第 6 节的「降噪执行版提示词」）。

## 4. 问题发现：否定词漏译（语义反转）

### 4.1 现象

测试输入：

```
Now it's clear: the Aliyun mirror does NOT mirror the PEP 503 subpages,
only the flat listing. So I need to use --find-links.
```

Qwen3.5-0.8B 早期输出：

```
阿里云镜像镜像 PEP 503 子页面，但只镜像扁平列表……
```

**说明：此输出同时暴露了两个相互独立的错误，并非笔误：**

1. **否定词漏译（语义反转）**：`does NOT mirror` 被翻成「镜像」（漏译 `NOT`），「不镜像」变「镜像」，技术判断彻底相反。
2. **名词/动词混淆（叠词）**：主语名词 `mirror`（镜像源）与谓语动词 `mirror`（动词「镜像」）未加区分，直译导致「镜像镜像」叠词。

两者根因不同、修复侧重点也不同：前者靠「强制高亮否定词」修复；后者靠「术语区分 + 语境理解」修复（见第 6 节术语清单中 `mirror` 未单列，属遗留待补）。

### 4.2 根因

小模型（0.8B）的注意力机制倾向于：

1. 优先提取**主干**（主语+谓语+宾语）：`Aliyun mirror` + `mirror` + `subpages`；
2. **弱化修饰词**（否定词 `NOT`、限定词 `only`）——生成阶段被当作「噪音」压缩丢弃。

这是**参数规模限制下的信息压缩偏差**，而非模型「不听话」。因此「要求它准确」不够，必须用**工程化提示词强制高亮这些词**。

## 5. A/B 实测（数据说话）

为验证修复方案，对同一条出错日志跑了两个方案：

### 5.1 方案 A：降噪执行版提示词（大模型顾问蓝本）

思路：强制「前置找否定词→高亮→四段式→术语括号解释→输出自检」。

**结果**：

```
一、一句话概括：阿里云镜像【不】镜像 PEP 503 子页面，【只】镜像扁平列表。
二、逐句翻译：
   1. 现在很清楚了：阿里云镜像【不】镜像 PEP 503 子页面，【只】镜像扁平列表。
      （PEP 503 是 Python 包索引的目录格式规范）
   2. 所以，我需要使用 --find-links。
      （--find-links 是指定额外下载来源的 pip 参数）
三、Agent 此刻在想什么：阿里云镜像【不】镜像……得用 --find-links 了。
四、结论 / 下一步：使用 --find-links 参数。
```

### 5.2 方案 B：极简提示词 + 输入侧预处理

思路：把 `NOT`/`only` 在原文里大写强调，再用极简提示词翻。

**结果**：

```
现在清楚了：阿里云镜像【只】【不】镜像 PEP 503 的子页面，【只】是扁平列表。所以必须用 --find-links。
```

### 5.3 对比结论

| 指标 | 方案 A（降噪版）| 方案 B（预处理）|
|---|---|---|
| `NOT` 翻对 | ✅ 【不】 | ❌ 「只不」（双重否定错乱） |
| `only` 翻对 | ✅ 【只】 | ❌ 「只是」 |
| 术语括号解释 | ✅ 有 | ❌ 无 |
| 结构完整 | ✅ 四段齐全 | ❌ 单句 |
| **判定** | **✅ 采用** | **❌ 弃用** |

**核心结论**：提示词不增加信息，而是**重新分配注意力**——结构化强制拆解 + 高亮，能让 0.8B 把「次要词」捡回来。

**方案 B 失败的机理**：输入侧把 `NOT`/`only` 大写、再叠加 `【只】【不】` 双重标记，反而让 0.8B 在生成时**混淆了否定/限定的语义范围**——它无法判断这些强调词修饰的是 `mirror` 还是整个从句，于是产出「只不镜像」「只是扁平列表」这种自相矛盾的叠加。换言之，「加粗强调」对已经注意力有限的 0.8B 不是增益，而是**再一次引入歧义噪音**。

## 6. 定稿：降噪执行版提示词

以下为**专为 0.8B 小模型、经实测验证**的提示词，落地到 `serve.py` 的 System 指令：

```text
你是一位技术日志翻译官。请严格遵守以下规则，不要跳过任何步骤：

## ⚠️ 第一条规则（防错最重要）
在开始翻译前，先找出原文中的所有否定词（NOT、never、without、except）
和限定词（only、exactly、solely）。用【高亮】标记它们，
例如：阿里云【不】镜像 PEP 503 子页面，【只】镜像扁平列表。

## 📋 输出格式（必须按此顺序）
### 一、一句话概括
用一句话说清这段日志在讲什么，但【必须】保留原句中的否定/限定含义。
### 二、逐句翻译
将原文拆成 1-3 句，逐句翻译。每句翻译后，用括号补充说明术语含义。
### 三、Agent 此刻在想什么
用 1-2 句话推测 Agent 的意图（基于翻译后的内容）。
### 四、结论 / 下一步
给出当前状态和下一步建议。

## 🔧 强制术语解释清单
遇到以下术语，【必须】在翻译后加括号中文解释：
- pip → （Python 包安装工具）
- PEP 503 → （Python 包索引的目录格式规范）
- --find-links → （指定额外下载来源的 pip 参数）
- CUDA → （英伟达显卡计算平台）
- wheel → （Python 预编译安装包格式）

开始翻译。
```

> 注：报告蓝本中的「输出前自检（默念补漏）」经实测观察，0.8B 并未真正执行元认知步骤（它直接输出就对了），该条可保留但非必需。

## 9. 遗留事项与建议

1. **落地**：将第 6 节提示词写入 `serve.py`（待用户确认落地方式）。
2. **界面微调**：面板宽度从 250px 收至 236px 已落地；如仍遮挡，可继续逐字符收窄。
3. **语言判断**：当前 `isMostlyEnglish` 判据较粗（会被「中文思考夹英文素材」误触发）。**改进方向**：先统计中文字符占比，若中文 < 30% 且文本含技术关键词（如 `pip`、`CUDA`、`torch`、`error`），再判定为英文技术日志——用「占比阈值 + 关键词」双重条件替代当前的单一字符计数。
4. **模型升级路径**：若后续硬件允许，升级 Qwen3.5-3B/7B 后可移除强制高亮，改回通用风格提示词。**显存成本估算**：0.8B ≈ 1.4GB → 3B ≈ 4.5GB（**超出当前 4GB 显存上限，会 OOM**）；→ 1.5B ≈ 2.5GB（仍在 4GB 范围内，可尝试，推理速度预计 3s→5s）。**结论：4GB 显存下，0.8B 是当前安全上限，1.5B 可尝试但需实测是否 OOM。**

## 10. 反直觉发现（值得单独记录）

在 A/B 实测中暴露了一个重要结论：

> **「输出前自检（让模型默念补漏）」这种元认知指令，对 0.8B 实际无效——它并没有真的执行自省，只是碰巧直接输出正确。真正起作用的，是「强制结构化 + 前置高亮」把否定词从「噪音」升级为「必须处理的对象」。**

**含义**：对小模型而言，**「逼迫它按固定结构拆解 + 在输入端显式标出关键词」比「要求它自我反思」有效得多。** 这推翻了「小模型缺的是理解和自控」的直觉，实则是「小模型缺的是注意力指向」——工程化提示词要做的不是教它思考，而是**替它把注意力掰到该看的地方**。
